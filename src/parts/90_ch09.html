المشروع التطبيقي: عدّاد أذكار خطوة خطوة

في هذا الفصل تبني تطبيقًا كاملًا بيديك عبر عشر مراحل، كل مرحلة تنتهي بشيء يعمل على شاشتك ولقطة Git. الكود الوارد هنا ليس مقتطفات نظرية: هو مشروع حقيقي جُمِّع بـ Flutter 3.41 واجتاز flutter analyze بلا ملاحظات و7 اختبارات آلية أثناء إعداد هذا الدليل. المشروع الكامل مرفق مع الدليل في مجلد example_dhikr_counter. لكن لا تنسخه دفعة واحدة؛ اكتبه مرحلة مرحلة كما هو مرتب، فالهدف أن تفهم لماذا تنمو الفكرة بهذا الترتيب، لا أن تحصل على تطبيق.

قبل أن تبدأ

تأكد أن flutter doctor راضٍ عن بيئتك (الفصل الخامس)، وأن هاتفك أو المحاكي يظهر في flutter devices. وأنشئ مستودع Git من اللحظة الأولى.

المرحلة 1: صياغة الفكرة والنطاق الأول

لن نكتب كودًا. نأخذ نموذج المتطلبات من الفصل السادس ونثبّت النطاق الأول بجملة واحدة: «شاشة عدّ واحدة بذكر ثابت، زر كبير يزيد العدد، تصفير مع تأكيد، والعدد يبقى بعد إغلاق التطبيق». لا قائمة، لا إحصاءات، لا إشعارات. اكتب هذه الجملة في ملف README.md في مجلد المشروع مع قائمة «مؤجّل» تضع فيها كل فكرة تخطر لك أثناء العمل بدل تنفيذها.

لماذا هذا النطاق؟ لأنه يجبرنا على المرور بالمفاهيم الأربعة الأساسية (واجهة، حالة، تخزين، حالات غير معتادة) في أصغر شكل ممكن. كل ما سيأتي بعده توسيع لا تأسيس.

المرحلة 2: رسم الشاشات وتحديد التنقل

على ورقة: مستطيل بنسبة الهاتف. في الأعلى شريط عنوان فيه «عدّاد الأذكار» وزرّان أيقونيان (قائمة، تصفير). في الوسط نص الذكر، تحته الرقم كبيرًا جدًا، تحته «الهدف: 33». في الأسفل زر يملأ العرض بارتفاع كبير مكتوب عليه «سَبِّح». مستطيل ثانٍ لشاشة القائمة: قائمة عمودية، كل صف فيه نص الذكر وهدفه، وعلامة صح أمام المختار. سهم من زر القائمة إلى الشاشة الثانية، وسهم عودة من أي صف إلى الأولى.

ثلاثة قرارات تخرج من الرسم فورًا: (1) الزر في أسفل الشاشة حيث يصل الإبهام بيد واحدة؛ (2) الرقم هو أكبر عنصر لأنه ما يُقرأ من بعيد؛ (3) شاشة القائمة تُفتح فوق شاشة العدّ وتُغلق بالاختيار، فلا نحتاج إلى تنقل معقد.

المرحلة 4: جعل زر العدّ يعمل وإدارة حالة العدّاد

الآن أول «حالة» حقيقية. الرقم لم يعد ثابتًا؛ يتغير مع كل نقرة. في Flutter، الـ widget الذي يحمل حالة متغيرة هو StatefulWidget، ودالة setState تخبر Flutter بأن يعيد الرسم:

import 'package:flutter/material.dart';

/// المرحلة 4: أول "حالة" حقيقية. StatefulWidget + setState.
class SimpleCounterScreen extends StatefulWidget {
  const SimpleCounterScreen({super.key});

  @override
  State<SimpleCounterScreen> createState() => _SimpleCounterScreenState();
}

class _SimpleCounterScreenState extends State<SimpleCounterScreen> {
  int _count = 0; // الحالة: قيمة تتغير مع الزمن وتؤثر في ما يُعرض

  void _increment() {
    // setState تخبر Flutter: "الحالة تغيّرت، أعد بناء هذه الشاشة".
    setState(() => _count++);
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('عدّاد الأذكار')),
      body: Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [
          Text('$_count', style: const TextStyle(fontSize: 72)),
          const SizedBox(height: 32),
          FilledButton(onPressed: _increment, child: const Text('سَبِّح')),
        ],
      ),
    );
  }
}

شغّل وانقر. الرقم يزيد. انقر بسرعة عشرين مرة: هل ضاعت نقرات؟ (لا؛ Flutter يعالج اللمسات بالتسلسل). أدر الشاشة: الرقم عاد إلى الصفر؟ لا، لأن حالة الـ widget تبقى عند الدوران. لكن أغلق التطبيق تمامًا وافتحه: الرقم صفر. هذه هي مشكلة المرحلة التالية.

لقطة Git. ما تعلمته: الفرق بين StatelessWidget (يرسم من مدخلاته فقط) وStatefulWidget (يملك حالة تتغير)، وأن setState لا «تغيّر النص» بل تعلن أن الحالة تغيّرت فيُعاد بناء الواجهة من الحالة الجديدة.

انتبه: لماذا لن نبقى على setState؟

setState ممتازة للحالة المحلية. لكن العدد الآن يحتاج إلى الحفظ (طبقة بيانات) وستحتاجه شاشة القائمة لاحقًا (شاشة أخرى). حالة تحتاجها أكثر من شاشة وتلمس التخزين هي «حالة تطبيق»، ومكانها خارج الـ widget. لذلك سنعيد التنظيم في المرحلة التالية قبل أن يكبر الكود، لا بعده.

المرحلة 5: حفظ العدّاد محليًا واستعادته عند فتح التطبيق

هنا نبني البنية التي ستحمل بقية المشروع: نموذج، ومخزن مجرّد بتنفيذين، ومتحكم يحمل الحالة. نضيف حزمة التخزين البسيط:

flutter pub add shared_preferences

أولًا النموذج lib/models/dhikr.dart. نكتبه الآن رغم أننا ما زلنا بذكر واحد، لأن «العدد» يخص ذكرًا ما، والمعرّف الثابت سيسمح لنا بحفظ عدد لكل ذكر لاحقًا دون تغيير صيغة التخزين:

/// نموذج (Model) يمثّل ذِكرًا واحدًا في القائمة.
/// النموذج "غبي" عمدًا: يحمل البيانات فقط ولا يعرف شيئًا عن الشاشات أو التخزين.
class Dhikr {
  const Dhikr({required this.id, required this.text, required this.target});

  /// معرّف ثابت لا يتغير حتى لو عدّلنا النص لاحقًا.

  /// نص الذكر كما يظهر للمستخدم.
  final String text;

  /// العدد المستهدف (مثل 33 أو 100).
  final int target;
}

ثانيًا طبقة البيانات lib/data/counter_store.dart. لاحظ ثلاثة قرارات: عقد مجرّد CounterStore حتى نستبدل التخزين في الاختبار؛ التخزين كخريطة «معرّف ← عدد» في نص JSON واحد لأن البيانات صغيرة؛ ومعالجة البيانات التالفة من الآن (سنعود إليها في المرحلة 7):

import 'dart:convert';

import 'package:shared_preferences/shared_preferences.dart';

/// عقد (واجهة مجرّدة) يصف ما نحتاجه من "مخزن العدّادات" دون تحديد كيفية التخزين.
/// فائدة العقد: يمكن استبدال التخزين الحقيقي بنسخة في الذاكرة أثناء الاختبار.
abstract class CounterStore {
  /// يُرجع خريطة: معرّف الذكر -> العدد المحفوظ.
  Future<Map<String, int>> loadCounts();

  /// يحفظ الخريطة كاملة. الحجم صغير جدًا فلا حاجة لقاعدة بيانات هنا.
  Future<void> saveCounts(Map<String, int> counts);
}

/// تنفيذ حقيقي يعتمد على حزمة shared_preferences.
/// نخزّن الخريطة كنص JSON واحد تحت مفتاح واحد.
class SharedPrefsCounterStore implements CounterStore {
  SharedPrefsCounterStore([SharedPreferencesAsync? prefs])
      : _prefs = prefs ?? SharedPreferencesAsync();

  final SharedPreferencesAsync _prefs;
  static const _key = 'dhikr_counts_v1';

  @override
  Future<Map<String, int>> loadCounts() async {
    final raw = await _prefs.getString(_key);
    if (raw == null || raw.isEmpty) return {};
    try {
      final decoded = jsonDecode(raw);
      if (decoded is! Map) return {};
      // نتحقق من نوع كل قيمة: أي قيمة تالفة تُهمل بدل أن تُسقط التطبيق.
      return {
        for (final entry in decoded.entries)
          if (entry.value is int && (entry.value as int) >= 0)
            entry.key.toString(): entry.value as int,
      };
    } on FormatException {
      // بيانات تالفة (مثلًا من إصدار قديم): نبدأ من الصفر بدل الانهيار.
      return {};
    }
  }

  @override
  Future<void> saveCounts(Map<String, int> counts) {
    return _prefs.setString(_key, jsonEncode(counts));
  }
}

/// تنفيذ في الذاكرة فقط، للاختبارات وللتجربة السريعة.
class InMemoryCounterStore implements CounterStore {
  final Map<String, int> _data = {};

  @override
  Future<Map<String, int>> loadCounts() async => Map.of(_data);

  @override
  Future<void> saveCounts(Map<String, int> counts) async {
    _data
      ..clear()
      ..addAll(counts);
  }
}

ثالثًا المتحكم lib/state/counter_controller.dart. يرث ChangeNotifier، يحمل الحالة، ويحفظ بعد كل تغيير. لا يعرف شيئًا عن الـ widgets:

import 'package:flutter/foundation.dart';

import '../data/counter_store.dart';
import '../models/dhikr.dart';

/// "عقل" الشاشة: يحمل الحالة (الذكر الحالي وعدّه) ويبلّغ الواجهة عند تغيّرها.
/// لا يعرف شيئًا عن الـ Widgets، لذا يمكن اختباره دون تشغيل واجهة.
class CounterController extends ChangeNotifier {
  CounterController({required CounterStore store, List<Dhikr>? adhkar})
      : _store = store,
        adhkar = adhkar ?? defaultAdhkar;

  final CounterStore _store;
  final List<Dhikr> adhkar;

  Map<String, int> _counts = {};
  Dhikr? _current;
  bool _loaded = false;

  bool get isLoaded => _loaded;
  Dhikr get current => _current ?? adhkar.first;
  int get count => _counts[current.id] ?? 0;
  bool get reachedTarget => count >= current.target;

  /// يُستدعى مرة واحدة عند فتح التطبيق لاستعادة ما حُفظ سابقًا.
  Future<void> load() async {
    _counts = await _store.loadCounts();
    _loaded = true;
    notifyListeners();
  }

  void selectDhikr(Dhikr dhikr) {
    _current = dhikr;
    notifyListeners();
  }

  /// يزيد العدّاد ويحفظ. نحفظ بعد كل نقرة لأن الكتابة صغيرة ورخيصة،
  /// ولأن المستخدم قد يغلق التطبيق في أي لحظة.
  Future<void> increment() async {
    _counts[current.id] = count + 1;
    notifyListeners();
    await _store.saveCounts(_counts);
  }

  Future<void> reset() async {
    _counts.remove(current.id);
    notifyListeners();
    await _store.saveCounts(_counts);
  }
}

لماذا نحفظ بعد كل نقرة لا عند الخروج؟ لأن الأنظمة تقتل التطبيقات في الخلفية دون إنذار، ولا يوجد حدث «قبل الإغلاق» موثوق على الهاتف. الكتابة هنا بضع مئات من البايتات ولا تُلاحظ. في تطبيق يحفظ صورًا كبيرة كان القرار سيختلف (حفظ عند اكتمال الإدخال).

البنية جاهزة، فالإضافة الآن صغيرة: شاشة قائمة تعرض controller.adhkar، والنقر على صف يستدعي selectDhikr ويعود. أنشئ lib/screens/dhikr_list_screen.dart:

ثم شاشة العدّ الكاملة lib/screens/counter_screen.dart، وفيها أيضًا حوار تأكيد التصفير ومؤشر التحميل والاهتزاز (المرحلة 7 تشرح تلك الأجزاء):

import 'package:flutter/material.dart';
import 'package:flutter/services.dart';

import '../state/counter_controller.dart';
import 'dhikr_list_screen.dart';

class CounterScreen extends StatelessWidget {
  const CounterScreen({super.key, required this.controller});

  final CounterController controller;

  Future<void> _confirmReset(BuildContext context) async {
    final ok = await showDialog<bool>(
      context: context,
      builder: (context) => AlertDialog(
        title: const Text('تصفير العدّاد؟'),
        content: const Text('سيبدأ العدّ من الصفر لهذا الذكر.'),
        actions: [
          TextButton(
            onPressed: () => Navigator.pop(context, false),
            child: const Text('إلغاء'),
          ),
          FilledButton(
            onPressed: () => Navigator.pop(context, true),
            child: const Text('تصفير'),
          ),
        ],
      ),
    );
    if (ok == true) await controller.reset();
  }

  Future<void> _onTap() async {
    final wasBelowTarget = !controller.reachedTarget;
    await controller.increment();
    // اهتزاز خفيف عند بلوغ الهدف (يعمل على الجهاز الحقيقي، لا على المحاكي غالبًا).
    if (wasBelowTarget && controller.reachedTarget) {
      HapticFeedback.mediumImpact();
    } else {
      HapticFeedback.selectionClick();
    }
  }

  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);
    return ListenableBuilder(
      listenable: controller,
      builder: (context, _) {
        if (!controller.isLoaded) {
          return const Scaffold(
            body: Center(child: CircularProgressIndicator()),
          );
        }
        final dhikr = controller.current;
        return Scaffold(
          appBar: AppBar(
            title: const Text('عدّاد الأذكار'),
            actions: [
              IconButton(
                tooltip: 'اختيار ذكر',
                icon: const Icon(Icons.list_alt),
                onPressed: () => Navigator.push(
                  context,
                  MaterialPageRoute<void>(
                    builder: (_) => DhikrListScreen(controller: controller),
                  ),
                ),
              ),
              IconButton(
                tooltip: 'تصفير',
                icon: const Icon(Icons.refresh),
                onPressed: () => _confirmReset(context),
              ),
            ],
          ),
          body: SafeArea(
            child: Column(
              children: [
                const Spacer(),
                Padding(
                  padding: const EdgeInsets.symmetric(horizontal: 24),
                  child: Text(
                    dhikr.text,
                    textAlign: TextAlign.center,
                    style: theme.textTheme.headlineMedium,
                  ),
                ),
                const SizedBox(height: 24),
                Semantics(
                  // نص يقرؤه قارئ الشاشة (TalkBack / VoiceOver).
                  label: 'العدد الحالي ${controller.count} من ${dhikr.target}',
                  child: Text(
                    '${controller.count}',
                    style: theme.textTheme.displayLarge?.copyWith(
                      fontWeight: FontWeight.w800,
                      color: controller.reachedTarget
                          ? theme.colorScheme.primary
                          : null,
                    ),
                  ),
                ),
                Text('الهدف: ${dhikr.target}',
                    style: theme.textTheme.bodyLarge),
                const Spacer(),

  group('CounterController', () {

      final controller =
          CounterController(store: InMemoryCounterStore(), adhkar: testAdhkar);
      await controller.load();

      expect(controller.count, 0);
      await controller.increment();
      await controller.increment();
      expect(controller.count, 2);
      expect(controller.reachedTarget, isFalse);
    });

    test('يبلغ الهدف عند العدد المستهدف', () async {
      final controller =
          CounterController(store: InMemoryCounterStore(), adhkar: testAdhkar);
      await controller.load();
      for (var i = 0; i < 3; i++) {
        await controller.increment();
      }
      expect(controller.reachedTarget, isTrue);
    });

    test('يستعيد العدد المحفوظ عند إعادة الفتح', () async {
      final store = InMemoryCounterStore();
      final first = CounterController(store: store, adhkar: testAdhkar);
      await first.load();
      await first.increment();

      // "إعادة فتح التطبيق": متحكم جديد بنفس المخزن.
      final second = CounterController(store: store, adhkar: testAdhkar);
      await second.load();

    });

    test('التصفير يعيد العدد إلى الصفر ويحفظ', () async {
      final store = InMemoryCounterStore();
      final controller = CounterController(store: store, adhkar: testAdhkar);
      await controller.load();
      await controller.increment();
      await controller.reset();
      expect(controller.count, 0);
      expect(await store.loadCounts(), isEmpty);
    });
  });
}

المرحلة 9: تحسين الواجهة العربية

عد إلى main.dart. السطور الثلاثة الخاصة باللغة تفعل الكثير: locale: Locale('ar') يجعل العربية لغة التطبيق، وGlobalMaterialLocalizations.delegates (من حزمة flutter_localizations المدمجة، أضفها بـ flutter pub add flutter_localizations --sdk=flutter) يوفر النصوص العربية لعناصر Material الجاهزة (أزرار الحوارات، tooltips الرجوع) ويقلب اتجاه الواجهة كلها إلى RTL. لاحظ في التطبيق: زر الرجوع في شاشة القائمة صار على اليمين، وعلامة الصح على اليسار، دون أن نكتب سطرًا لذلك.

قائمة مراجعة عربية لهذا المشروع:

  • كل نص عربي مكتوب بحركات حيث تهم القراءة (نصوص الأذكار) وبدونها حيث لا تهم (الأزرار) للوضوح.
  • الأرقام: قررنا عرضها بالأرقام الغربية ('${controller.count}') لوضوحها من بعيد. لو أردت الأرقام الهندية فاستخدم NumberFormat.decimalPattern('ar') من حزمة intl واختبر الناتج على الجهاز.
  • لا يوجد في هذا المشروع EdgeInsets.only(left:) ولا Alignment.centerLeft؛ استخدمنا symmetric وDirectional. راجع كودك بالبحث عن left وright.
  • الخط: الخط الافتراضي في Flutter للعربية مقبول لكنه عام. لخط مخصص (مثل خطوط Google العربية) أضف ملفات الخط إلى pubspec.yaml واضبطه في ThemeData.fontFamily. تأكد من رخصة الخط.
  • جرّب التطبيق بلغة الجهاز الإنجليزية أيضًا: لأننا ثبّتنا locale على العربية فسيبقى عربيًا، وهذا مقصود في تطبيق عربي. لو أردت لغتين فاحذف locale الثابت واستخدم ملفات ARB كما في وثائق الترجمة.

المرحلة 10: تجهيز إصدار تجريبي

ثلاثة أشياء لـ Android يمكنك إتمامها بالكامل على جهازك:

(أ) الأيقونة والاسم. اسم التطبيق الظاهر في android/app/src/main/AndroidManifest.xml (android:label) وفي ios/Runner/Info.plist (CFBundleDisplayName). الأيقونة عبر حزمة flutter_launcher_icons من صورة 1024×1024 واحدة.

(ب) مفتاح الرفع. أنشئ keystore مرة واحدة واحفظه خارج المشروع وفي نسخة احتياطية:

keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

ثم ملف android/key.properties (وأضفه إلى .gitignore فورًا) واربطه في android/app/build.gradle.kts كما تشرح وثائق Flutter خطوة بخطوة: https://docs.flutter.dev/deployment/android

(ج) رقم الإصدار والبناء. في pubspec.yaml: version: 0.1.0+1. ثم:

flutter build appbundle --release
# الناتج: build/app/outputs/bundle/release/app-release.aab
flutter build apk --release --split-per-abi
# ملفات APK لإرسالها مباشرة لمختبرين خارج المتجر

ثبّت نسخة الإصدار على هاتفك واختبرها بالقائمة اليدوية نفسها؛ وضع release قد يكشف ما لا يظهر في debug. ثم ارفع الـ aab إلى مسار الاختبار الداخلي في Play Console وأضف زملاءك بعناوين بريدهم. اقرأ تقرير ما قبل الإطلاق حين يصدر.

لـ iOS اتبع الفصل الخامس: مستودع GitHub ← Codemagic ← مفتاح App Store Connect ← بناء ورفع إلى TestFlight ← زميل يملك iPhone. قبل البناء الأول راجع ios/Runner/Info.plist: هذا التطبيق لا يستخدم أي إذن فلا نصوص شرح مطلوبة، لكن تطبيق الفواتير سيحتاج إلى NSCameraUsageDescription وNSPhotoLibraryUsageDescription.

وسم الإصدار: git tag v0.1.0 && git push --tags. وسجّل في CHANGELOG.md ما يتضمنه.
